## Session 1, continued — live user QA pass

The user tested the rebuilt app for real and reported two issues. Investigated both live with a real browser (not guessed) rather than trusting either symptom description or my own earlier "done" claims at face value.

**1. "The Supabase image link works directly, but the image doesn't load in the console."** Real bug, found and fixed. `frontend/src/components/ui/QuestionImage.tsx`'s `<img>` was hidden via a `display:none` Tailwind class until its `onLoad` fired (to avoid a broken-image flash) — but it also carried `loading="lazy"`. A `display:none` element has no layout box, so the browser's native lazy-loading can never determine it's "near the viewport" and simply never issues the fetch. The two mechanisms deadlocked: the image needed to load to become visible, but needed geometry (i.e. to already be visible) for lazy-loading to ever fetch it. Confirmed with a real headless-browser diagnostic (`db/scripts/manual/diagnose-image-rendering.ts`) both ways: before the fix, the network tab showed zero requests for the image and `el.currentSrc` stayed empty indefinitely; after removing `loading="lazy"`, a real `200 image/png` response arrives and `el.complete`/`naturalWidth` populate within ~500ms, and the element's class correctly switches off `hidden`. Verified via `npm run build` + a fresh browser run against the rebuilt bundle. Fix applies to every caller (`TestTakingView`, `AttemptReviewView`) — none of them show a list of many images where lazy-loading would have been a legitimate win in the first place; each only ever shows the one image relevant to the currently-visible question.
